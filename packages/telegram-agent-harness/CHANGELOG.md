# Changelog

## [Unreleased]

### Added
- Telegram Mini App with session status, session-bound Yes/No approvals, and freshness-labelled fleet/blocker/merge-queue snapshots. The dedicated Dokploy service serves static assets and relays API calls over an authenticated outbound WebSocket from the local daemon; bot polling and approval storage stay local. Telegram launch credentials are HMAC-validated within five minutes and exchanged for an eight-hour, bot-bound app session. Slot-local `miniapp.json` holds the HTTPS URL and relay secret; `/app` and per-operator menu buttons open it. Missing sources remain explicitly unavailable; merge execution and transcript/diff views are not included.
- Config-driven Telegram bot slot eligibility matching cwd globs (defaulting to any project) and prioritizing specific project affinity over shared pool slots.
- Detailed slot lease busy diagnostics exposing session ID, project path, and owner PID (`ClaimResult.busyHolders` and detailed formatted reason).
- HTTP 409 conflict bounded exponential backoff, diagnostic warning logs, and host session error notifications on Telegram poller exhaustion.
- `telegram_question` tool asking the operator a labeled-choice question on the session's Telegram route, returning only that question's answer and never an approval.
- `telegram_message` tool sending lane-attributed updates with durable reply context, so an operator reply routes back to the originating lane.
- `telegram_dashboard` tool refreshing one pinned fleet dashboard from observed lane, blocker and merge-queue state on a 30-second coalesced edit.
- Telegram free-text replies and callback selections answer the question they reply to instead of starting a new operator turn.
- Configured message thread id is read from the leased channel so a forum-topic channel receives messages in its own topic.
- Standalone Telegram bot daemon (`daemon/`): polls opted-in bot tokens machine-wide and drives Veyyon sessions through the GUI host action protocol, so a bot keeps answering with no session open in the project. Slots opt in with `"daemon": true` in `manifest.json` (or `VEYYON_TELEGRAM_DAEMON_SLOTS`); the daemon holds an ordinary pool lease per slot, so in-session pollers see the slot as busy and the single-poller-per-token invariant is unchanged. Durable per-chat session routing and per-entry delivery claims in `~/.veyyon/telegram/daemon.db` keep a restart from replaying a transcript into the operator's chat. Chat commands: `/sessions`, `/attach <id>`, `/new [path]`, `/detach`, `/where`. CLI: `bun daemon/main.ts run|status|stop|check`.
- `defaultProject` on a manifest slot: the absolute directory a daemon-owned slot's sessions are created in when it declares no `preferredProjects`. A bot that serves every project declares no affinity, and an empty declaration resolves to no directory, so `/new` had nowhere to start a session.
- `daemon/main.ts run` waits out a slot that is held instead of exiting 75. A token claimed by an interactive session frees itself when that session exits or its operator runs `/telegram release`, and a detached daemon that gave up at startup is not there to notice; it now retries every 10s (`VEYYON_TELEGRAM_CLAIM_RETRY_MS`) and logs a skip only when the reason changes. Exiting on release is unchanged once a slot has actually been polled, so `/release` still stops the daemon.

### Fixed
- Preserve empty preference list for discovered Telegram bot slots lacking explicit configuration, restoring any-project eligibility default and removing hardcoded comment examples.
- Operator tools resolve their Telegram channel on every call and refuse a session they do not own, so a tool retained across a hot reload can no longer post into another session's chat.
- Telegram question, dashboard and lane-provenance services stop when the lease is relinquished or the session shuts down, instead of leaving timers writing to a released channel.
- A slot marked `"daemon": true` is no longer offered to the in-session pool. The lease alone did not hold: a slot declaring no projects is eligible for every project, so any terminal opened while the daemon was down claimed the operator's daemon bot and kept it for the session's lifetime — after which the daemon correctly refuses to steal it back, and the bot keeps answering from the in-session poller. The daemon still claims its slots by name (`acquireLeaseForSlot`), and a slot that never opted in is untouched.
- The dangerous-tool guard classifies what a command will execute instead of what its text looks like. The decode pipeline (`echo <b64> | base64 -d | sh`, `openssl enc -d -a`, `certutil -decode`) is now recognised from parsed pipeline stages, so a commit message, a comment or a quoted heredoc citing that pipeline is ordinary text again, while the pipeline itself is gated together with here-strings (`<<<`), heredocs consumed by a later pipeline stage, `$(...)` output reparsed by `eval`/`sh -c`, and fetch-into-interpreter cradles. Command names the lexer cannot resolve — `${IFS}` splitting, `{rm,-rf,/}`, `$A`, `${!var}`, escaped spellings — and code built at runtime (`exec(input())`, `Function(process.env.X)`, computed members, f-string and template interpolation) now require operator approval under the new `dynamic_code` category instead of being silently allowed. `decodeBase64` validates charset, length and a re-encode round trip, so ordinary text no longer decodes to mojibake that the guard then acts on. Coverage grew to the wrappers and spellings agents actually type: `sudo`/`timeout`/`npx`/`bunx`/`pnpm dlx`/`poetry run`, `python3.11`/`py`/`perl`/`ruby`/`php` with `-c`/`-e`/`--eval=VALUE`, PowerShell `-EncodedCommand` prefixes and POSIX combined clusters such as `bash -ce`, protected-branch deletion via `git branch -D`/`git update-ref -d`/`git push --prune`, DDL and deploys over the Supabase management and Dokploy HTTP APIs, destruction without `rm` (`rd`, `del`, `Remove-Item`, `find -delete`, `dd of=`, `truncate`, `>` truncation, out-of-tree docker bind mounts), remote `ssh <host> <command>`, deploy wrapper scripts, and the secret paths that actually hold credentials (`.env` family, `id_ed25519`, `agent.db`, `*.pem`, `credentials.json`, `.npmrc`). Everyday work stays unblocked: `grep -rn <production-ref> docs/` and `psql --version` no longer block, `.env.example` and `docs/env-production.md` read freely, and in-tree `rm`, `find -delete`, `dd`, redirection and bind mounts are untouched.
- The guard resolves a shell value into the words it really becomes, so `A='rm -rf /'; $A` is classified as the deletion it performs rather than as a one-word command, and a globbed program name (`/bin/r?`, `/bin/r[m]`) is gated as dynamically resolved instead of read literally. Writing is treated as destruction whatever binary performs it — `tee`, `sort -o`, `cp`/`mv`/`install`/`ln`/`rsync` destinations, `sed -i` operands and `open(path, "w")` from an eval payload now hit the same out-of-tree test as `rm`; `cmd /k` is a script host like `cmd /c`; a called Python `getattr(...)` is a computed member call, and a base64 payload handed to `eval` is also read as the shell line it decodes to. Reading a file no longer exempts it from the production-reference rule: only search tools (`grep`, `rg`, `ag`, `ack`) and read-only `git` verbs keep the exemption that makes the reference greppable, while `cat ~/prod.env`-style reads are gated.
- The guard reads a Windows path as a path: a word already carrying a drive prefix keeps its backslashes, so `Remove-Item -Path C:\ -Recurse -Force` is the drive-root deletion it is instead of a word that resolved inside the project, and `-Param:value` binds like `-Param value`. Five enumerations grew past the one spelling that slipped through each: brace alternation is detected anywhere in the program name (`/bin/{r,s}m`), `sed --in-place` joins `sed -i`, a `-t`/`--target-directory` destination is checked instead of the last operand, the exec family (`os.execv`/`execl`/`posix_spawn` and friends, plus `execa`) joins `os.system`, and the wrapper list gained the process wrappers that run their argument — `flock`, `chroot`, `unshare`, `strace`, `busybox` applet dispatch, `parallel ... ::: args`, `taskset`, `chrt`, `proxychains`, `firejail` and the reparsing `watch`, `script -c`, `su -c`, `runuser`.
