# Changelog

## [Unreleased]

### Added
- Telegram Mini App with session status, session-bound Yes/No approvals, and freshness-labelled fleet/blocker/merge-queue snapshots. The dedicated Dokploy service serves static assets and relays API calls over an authenticated outbound WebSocket from the local daemon; bot polling and approval storage stay local. Telegram launch credentials are HMAC-validated within five minutes and exchanged for an eight-hour, bot-bound app session. Slot-local `miniapp.json` holds the HTTPS URL and relay secret; `/app` and per-operator menu buttons open it. Missing sources remain explicitly unavailable; merge execution and transcript/diff views are not included.
- Config-driven Telegram bot slot eligibility matching cwd globs (defaulting to any project) and prioritizing specific project affinity over shared pool slots.
- Detailed slot lease busy diagnostics exposing session ID, project path, and owner PID (`ClaimResult.busyHolders` and detailed formatted reason).
- HTTP 409 conflict bounded exponential backoff, diagnostic warning logs, and host session error notifications on Telegram poller exhaustion.
- `telegram_question` tool asking the operator a labeled-choice question on the session's Telegram route, returning only that question's answer and never an approval.
- `telegram_message` tool sending lane-attributed updates with durable reply context, so an operator reply routes back to the originating lane.
- `telegram_dashboard` tool refreshing one pinned fleet dashboard from observed lane, blocker and merge-queue state on a 30-second coalesced edit.
- Telegram free-text replies and callback selections answer the question they reply to instead of starting a new operator turn.
- Configured message thread id is read from the leased channel so a forum-topic channel receives messages in its own topic.
- Standalone Telegram bot daemon (`daemon/`): polls opted-in bot tokens machine-wide and drives Veyyon sessions through the GUI host action protocol, so a bot keeps answering with no session open in the project. Slots opt in with `"daemon": true` in `manifest.json` (or `VEYYON_TELEGRAM_DAEMON_SLOTS`); the daemon holds an ordinary pool lease per slot, so in-session pollers see the slot as busy and the single-poller-per-token invariant is unchanged. Durable per-chat session routing and per-entry delivery claims in `~/.veyyon/telegram/daemon.db` keep a restart from replaying a transcript into the operator's chat. Chat commands: `/sessions`, `/attach <id>`, `/new [path]`, `/detach`, `/where`. CLI: `bun daemon/main.ts run|status|stop|check`.
- `defaultProject` on a manifest slot: the absolute directory a daemon-owned slot's sessions are created in when it declares no `preferredProjects`. A bot that serves every project declares no affinity, and an empty declaration resolves to no directory, so `/new` had nowhere to start a session.
- `daemon/main.ts run` waits out a slot that is held instead of exiting 75. A token claimed by an interactive session frees itself when that session exits or its operator runs `/telegram release`, and a detached daemon that gave up at startup is not there to notice; it now retries every 10s (`VEYYON_TELEGRAM_CLAIM_RETRY_MS`) and logs a skip only when the reason changes. Exiting on release is unchanged once a slot has actually been polled, so `/release` still stops the daemon.

### Fixed
- Preserve empty preference list for discovered Telegram bot slots lacking explicit configuration, restoring any-project eligibility default and removing hardcoded comment examples.
- Operator tools resolve their Telegram channel on every call and refuse a session they do not own, so a tool retained across a hot reload can no longer post into another session's chat.
- Telegram question, dashboard and lane-provenance services stop when the lease is relinquished or the session shuts down, instead of leaving timers writing to a released channel.
- A slot marked `"daemon": true` is no longer offered to the in-session pool. The lease alone did not hold: a slot declaring no projects is eligible for every project, so any terminal opened while the daemon was down claimed the operator's daemon bot and kept it for the session's lifetime — after which the daemon correctly refuses to steal it back, and the bot keeps answering from the in-session poller. The daemon still claims its slots by name (`acquireLeaseForSlot`), and a slot that never opted in is untouched.
- The dangerous-tool guard classifies what a command will execute instead of what its text looks like. The decode pipeline (`echo <b64> | base64 -d | sh`, `openssl enc -d -a`, `certutil -decode`) is now recognised from parsed pipeline stages, so a commit message, a comment or a quoted heredoc citing that pipeline is ordinary text again, while the pipeline itself is gated together with here-strings (`<<<`), heredocs consumed by a later pipeline stage, `$(...)` output reparsed by `eval`/`sh -c`, and fetch-into-interpreter cradles. Command names the lexer cannot resolve — `${IFS}` splitting, `{rm,-rf,/}`, `$A`, `${!var}`, escaped spellings — and code built at runtime (`exec(input())`, `Function(process.env.X)`, computed members, f-string and template interpolation) now require operator approval under the new `dynamic_code` category instead of being silently allowed. `decodeBase64` validates charset, length and a re-encode round trip, so ordinary text no longer decodes to mojibake that the guard then acts on. Coverage grew to the wrappers and spellings agents actually type: `sudo`/`timeout`/`npx`/`bunx`/`pnpm dlx`/`poetry run`, `python3.11`/`py`/`perl`/`ruby`/`php` with `-c`/`-e`/`--eval=VALUE`, PowerShell `-EncodedCommand` prefixes and POSIX combined clusters such as `bash -ce`, protected-branch deletion via `git branch -D`/`git update-ref -d`/`git push --prune`, DDL and deploys over the Supabase management and Dokploy HTTP APIs, destruction without `rm` (`rd`, `del`, `Remove-Item`, `find -delete`, `dd of=`, `truncate`, `>` truncation, out-of-tree docker bind mounts), remote `ssh <host> <command>`, deploy wrapper scripts, and the secret paths that actually hold credentials (`.env` family, `id_ed25519`, `agent.db`, `*.pem`, `credentials.json`, `.npmrc`). Everyday work stays unblocked: `grep -rn <production-ref> docs/` and `psql --version` no longer block, `.env.example` and `docs/env-production.md` read freely, and in-tree `rm`, `find -delete`, `dd`, redirection and bind mounts are untouched.
- The guard resolves a shell value into the words it really becomes, so `A='rm -rf /'; $A` is classified as the deletion it performs rather than as a one-word command, and a globbed program name (`/bin/r?`, `/bin/r[m]`) is gated as dynamically resolved instead of read literally. Writing is treated as destruction whatever binary performs it — `tee`, `sort -o`, `cp`/`mv`/`install`/`ln`/`rsync` destinations, `sed -i` operands and `open(path, "w")` from an eval payload now hit the same out-of-tree test as `rm`; `cmd /k` is a script host like `cmd /c`; a called Python `getattr(...)` is a computed member call, and a base64 payload handed to `eval` is also read as the shell line it decodes to. Reading a file no longer exempts it from the production-reference rule: only search tools (`grep`, `rg`, `ag`, `ack`) and read-only `git` verbs keep the exemption that makes the reference greppable, while `cat ~/prod.env`-style reads are gated.
- The guard reads a Windows path as a path: a word already carrying a drive prefix keeps its backslashes, so `Remove-Item -Path C:\ -Recurse -Force` is the drive-root deletion it is instead of a word that resolved inside the project, and `-Param:value` binds like `-Param value`. Five enumerations grew past the one spelling that slipped through each: brace alternation is detected anywhere in the program name (`/bin/{r,s}m`), `sed --in-place` joins `sed -i`, a `-t`/`--target-directory` destination is checked instead of the last operand, the exec family (`os.execv`/`execl`/`posix_spawn` and friends, plus `execa`) joins `os.system`, and the wrapper list gained the process wrappers that run their argument — `flock`, `chroot`, `unshare`, `strace`, `busybox` applet dispatch, `parallel ... ::: args`, `taskset`, `chrt`, `proxychains`, `firejail` and the reparsing `watch`, `script -c`, `su -c`, `runuser`.
- The guard classifies an execution by what it runs, not by which binary happens to be in fashion. Every interpreter's spelling of "run this string" is covered — `php -r`, `node -p`, `perl -E`, `ruby -e`, `Rscript -e`, `deno eval`, awk's program operand and AppleScript's `do shell script` — together with the backtick and `qx{}` escapes of Perl, Ruby and PHP, and `Deno.run`/`new Deno.Command` from an eval payload. `find -execdir`/`-ok`/`-okdir` joins `-exec`, and `find / … | xargs rm -rf` is read as the deletion of what the upstream stage enumerates. A DDL statement is gated whichever client carries it (`mysql -e`, `sqlite3`, `mongosh --eval`, `clickhouse-client`, `redis-cli flushall`) and whichever runner applies it without showing it (`prisma migrate deploy`, `drizzle-kit push`, `knex migrate:latest`, `sequelize db:*`, `typeorm migration:run`, `flyway`, `goose`, `atlas`, `rails db:migrate`, `manage.py migrate`). Deployment covers the platforms as well as Dokploy: `vercel --prod`, `netlify deploy`, `railway up`, mutating `kubectl` verbs, `helm upgrade`, `terraform apply`, `pulumi up`, `serverless deploy`, `ansible-playbook`, `eb deploy`, `gcloud … deploy` and the AWS service-update commands. Credentials are protected wherever they live: `.pgpass`, `.kube/config`, `.docker/config.json`, `.gnupg/`, `.git-credentials`, `secrets.json`, `terraform.tfstate` and `*.key`/`*.jks`, plus the managers that hand the same material out (`gh auth token`, `vault read`, `op read`, `aws secretsmanager get-secret-value`, `kubectl get secret`). `git branch -M main` and `git branch -f main` are protected-branch destruction like `git branch -D main`; `git worktree remove` and `git clean` face the out-of-tree test; and a remote transfer into a system path (`scp payload host:/etc/cron.d/job`) is destruction, while `scp file.txt host:/tmp/` stays the ordinary upload it is.
- The guard reads an HTTP call by the write it performs, whichever client spells it: curl's `-F`, wget's `--post-data`/`--method=POST`, PowerShell's `Invoke-RestMethod -Method POST` (and the `irm`/`iwr` aliases, whose single-dash parameter names bind by unambiguous prefix), so a management-API mutation or a deploy endpoint is gated through all of them, and a `DELETE` of `git/refs/heads/main` over REST — `curl`, or `gh api` with the token already attached — is the branch deletion it is. Windows launchers no longer hide their program: `start`, `start /b`, `start "title" …` and `Start-Process -FilePath … -ArgumentList` are classified by what they launch. `~/.ssh` joins the secret paths, so archiving or copying the directory is a credential read rather than a file copy.
- The guard follows a command through the indirection that hides it. A definition runs when it is called, so `function wipe { rm -rf / }; wipe` and `alias x='rm -rf /'; x` are classified by the body they install; `wsl`, `systemd-run`, `nsenter`, `docker exec`, `docker compose exec` and `kubectl exec` are classified by the command they run rather than by the wrapper's own name, which also stops `kubectl exec pod -- ls` from being read as a deployment; `schtasks /create /tr "…"` and `at <<< '…'` are classified by the payload they schedule; `git -c alias.x='!…'`, `git -c core.pager=…` and `ssh -o ProxyCommand=…` are classified by the command the setting hands to the tool; and `fish -c` joins the shells whose `-c` payload is reparsed.
- A delete whose target the lexer cannot resolve is approval-gated instead of allowed, so `rm -rf %SystemRoot%`, `rm -rf $env:SystemRoot` and `for d in / ; do rm -rf $d; done` face the operator rather than the filesystem. A target it can resolve is unchanged: `rm -rf ./dist`, `rm -rf "./my build dir"` and `rm -rf ./a/../b` stay ordinary, and `rm -rf /`, `~`, `..`, `//`, `/.`, `/tmp/../etc`, a UNC share and a drive root stay destruction however they are quoted, clustered, continued across lines or split by tabs.
- The guard reads an eval payload's executor through the module system that produced it: `require("node:child_process")`, a module bound through a variable and one reached via `process.mainModule.require` resolve to the same module as a bare `require`, so `.exec(...)` on any of them is the shell line it runs. `subprocess.getoutput`, `os.popen2/3/4`, `asyncio.create_subprocess_shell` and the variadic `create_subprocess_exec` join the executor family; `setTimeout("…")` is the code string the runtime evaluates rather than a callback; `process.binding` is gated as the raw process API the lexer cannot follow. A file sink is read by what it does to the path: a copy, move, rename, link or `shutil.copytree` clobbers its destination, `truncate`, `appendFile`, `createWriteStream`, `chmod` and `chown` mutate the path they name, and `Path(p)` waits for the method that decides — `.unlink()` deletes, `.write_text()` clobbers, `.open(mode)` follows its mode, `.read_text()` still only reads. In-tree work is untouched: a `Bun.$` template running the test suite, `fs.rmSync("./dist")`, `Path("./dist/report.json").write_text(...)` and `shutil.move("./a.txt", "./b.txt")` stay ordinary.
- The guard classifies the tool surfaces beside `bash` and `eval` by the act they perform, so the shell is no longer the only guarded route to the same effect. Creating or patching a file is a write wherever it happens: the `write` tool's path, every `[path#tag]` section header and `MV` destination in an `edit` patch, and an `ast_edit` path glob face the same out-of-tree and secret-path tests as a shell redirection, and in-tree work is untouched. Text sent into a live process (`launch` `send`) is the command line it becomes once that process is a shell, `browser` automation code is read as the Node payload it is — including a `uploadFile` of a private key, which is a credential read — and an `ssh` command is classified, not only scanned for a production host, because a system root, a protected ref and a production identifier mean the same thing on either side of the connection.
- An interpreter handed its program on standard input runs whatever the upstream stage produced, so `echo 'rm -rf /' | sh`, `printf … | bash -s`, `… | python3 -`, `… | node`, `… | powershell -` and `echo 'rm -rf /' | at now + 1 minute` are classified by the text they execute, and a relay whose output the lexer cannot prove (`cat bootstrap.sh | sh`) faces the operator instead of the filesystem. A stage that names a script is reading data, not code: `cat data.json | python3 scripts/process.py`, `cat access.log | node tools/report.js`, a `-c`/`-e` one-liner filter, `git log | head`, `curl … | jq` and `sort | uniq -c` stay ordinary.
- Hostile input can no longer stall the guard or escape it. Command substitution stops recursing past 32 levels and treats deeper nesting as unresolved, which turned a 200k-level bomb from a 15-second stall and then a `RangeError` thrown out of the hook into a 134ms approval gate, and any exception raised while classifying now fails closed rather than leaving the caller without a verdict. A NUL byte or an unpaired surrogate is removed before parsing in both the shell and eval lexers, so `\0rm -rf /\0` is the deletion it is and attacker text cannot forge the parser's own dynamic marker.
- A credential is classified by the path that is read, not by the tool or the spelling that reads it. A `search` file glob is a path expression, so `**/*.pem` over a home directory enumerates keys instead of passing as a harmless scope; a path riding behind a prefix is still that path, so `curl --data-binary @.env` is the env file it uploads; and a path built at runtime keeps the part the lexer can prove, so `readFileSync(process.env.HOME + "/.ssh/id_rsa")` is the key it reads and `execSync("rm -rf " + target)` is the deletion it performs, where both previously resolved to nothing at all. Ordinary work is untouched: `.env.example`, a project source read, a `**/*.ts` glob, an in-tree write to `"./out/" + name`, `scp ./dist.tgz builder@host:/tmp/` and `tar czf dist.tgz ./dist` stay allowed.
- The tool gate no longer switches itself off when the Telegram channel is missing. `onToolCall` returned early unless a poller was attached, but the guard is installed before the poller is built and stays installed when a later step of attachment fails — a slot whose `access.json` carries a malformed `message_thread_id` left the session with a live guard, no channel and every dangerous command allowed. The verdict now depends on the guard alone; sending the approval card is best effort, and a card that could not be delivered is named in the block reason so the agent asks the operator out of band instead of waiting on a card nobody received.
- A process started through a debugger is still a process. `debug` launches are classified by the program and arguments they run, an expression evaluated in the debuggee is read as the code it is in both the JavaScript and Python spellings, a custom DAP request is classified by the command line its arguments name, and `browser open` with an `app.path` is the binary it spawns — so `debug launch bash -c "rm -rf /"`, `evaluate __import__('os').system(…)` and a browser "app" that is really a shell face the operator instead of the filesystem. A subscript belongs to the value it indexes, so `open(os.environ['HOME'] + '/.ssh/id_rsa')` is the key it reads. Debugging stays ordinary: an in-tree program, a breakpoint, a stack trace, `len(items)` and an attach over CDP are untouched.
