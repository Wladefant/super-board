# merge-scan-allowlist.txt — REPOSITORY-ONLY exclusions for the release gates.
#
# This file is deliberately NOT part of the payload, and neither gate depends
# on it. `scan_merge_prohibitions` excludes its own module intrinsically and
# tells a prohibition statement from an active merge mechanism on its own;
# `scan_retired_status` excludes the module that DECLARES the retired statuses
# the same intrinsic way and tells a retirement mention from a status use. Both
# therefore run — and can report clean — on an installed tree, where this file
# does not exist. That was the whole defect: a safety gate that only worked in
# the repository it shipped from.
#
# What is left here is the handful of REPOSITORY-ONLY surfaces neither rule can
# reach, listed BY NAME:
#
#   1. the contract tests, the seeded fixtures and the release notes, which
#      must carry real merge literals in order to prove the scanner still
#      detects them;
#   2. the tests that feed the retired `Skipped` status to a canonicalizer in
#      order to prove it is refused. In code the value has to arrive bare, as
#      the argument being rejected, which is the one shape the retirement
#      classifier cannot read as a mention.
#
# There is deliberately no path heuristic — a rule like "skip anything under
# docs/" is exactly how a real merge path hides in a file called
# docs/deploy-helper.sh. Adding a line here is a decision somebody has to make
# and a reviewer can see.
#
# A trailing slash excludes a whole subtree.
#
# Every entry must be LOAD-BEARING: removing it must make a scan fail. An entry
# that excludes a file carrying no scanned literal is dead weight that still
# excludes the file — so the day somebody adds a real merge path to it, the gate
# stays green. `tests/test_human_merge_contract.py` fails on a stale entry for
# exactly that reason, and it is what pruned this list when the scanner stopped
# needing most of it.
